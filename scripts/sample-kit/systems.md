# システムごとの違い

技能名・成功段階・感情の一覧は、ここに書き写さない（アプリの `GAME_SYSTEMS` が正で、ここに写すと古くなる）。
書き始める前に `system` 工程で取り出すこと:

```
http://localhost:8000/index.html?steps=system&system=coc6   → browser_run_code_unsafe（run.js）
```

ここにあるのは、一覧からは読み取れない**書き分けの勘どころ**である。

## 早見表

| 項目 | エモクロア（`emoklore`） | CoC 6版（`coc6`） |
|---|---|---|
| GMの呼び名・GM向け情報 | DL（ディーラー）・`[DL]`・「DL向け：…」の章 | KP（キーパー）・`[KP]`・「KP向け：…」の章 |
| プレイヤー側の呼び名 | 共鳴者・PL | 探索者・PL |
| 固有の判定 | 共鳴判定 `[共鳴:強度/上昇/感情（分類）]` | SANチェック `[SAN:成功/失敗]`（結果行は成功・失敗・ファンブル） |
| 成功段階 | 7段階。ふだん使うのは極限成功・効果的成功・成功・失敗・致命的失敗。奇跡的成功・災厄級成功はまれ | クリティカル・スペシャル・成功・失敗・ファンブル |
| 技能の値の書き方 | `"観察眼:Lv1"`（Lv0〜3。0は判定できない）。`＊` 付きの技能名はそのまま書く | `"目星:60"`（パーセント）。「運転（任意）」は「運転（自動車）」のように埋めて書く |
| 能力値（status のキー） | `str dex spi sen int cha soc luck`（1〜6）、派生 `hp mp resonance` | `str con pow dex app siz int edu`（3〜18が目安）、派生 `hp mp san idea luck know db` |
| NPCの感情 | `emotions: ["孤独（傷）", …]`（感情名（分類）） | 無し |
| プロフィール | `age gender occupation`（どちらも共通） | 同左 |
| 人数・HO | HOで書くことが多い（HO1・HO2…）。HOの情報は公開対象をそのHOに絞る | 人数の幅で書く。基本情報に「探索者の作成」の見出し |
| 怪異の作り方 | 伝承をもとにした怪異。感情と結びつける（何の感情から生まれたか） | 神話の雰囲気を持つ独自の存在。公式の怪物・神格のデータは使わない |

## エモクロア

- 共鳴判定は、怪異と共鳴者の感情が触れ合う場面に置く。直後の右の段（`>> …`）に「誰が判定するか」「上昇した共鳴度で何が起きるか」を書く。
- 共鳴度が上がることの怖さと意味を、DL向けの章で説明しておく。
- 感情は `EMOKLORE_EMOTIONS` の分類（欲望・情念・理想・関係・傷）から選ぶ。NPCの感情と、そのNPCの物語上の役割を合わせる。

## CoC 6版

- SANチェックの値は、恐怖の大きさで段階的に上げる（例: `0/1` → `1/1D3` → `1/1D6` → `1D3/1D6` → `1D6/1D20`）。よく使う組み合わせは `sanPresets`。
- クトゥルフ神話技能は、ふつうの探索者は0%から始まる。神話の知識で真相に近づく道を作るなら、それ以外の道も用意する。
- 舞台はルールの標準（1920年代のアメリカ）でなくてよい（既存サンプルは現代日本）。基本情報の「舞台」に書く。
- 判定には技能のほか、能力値・派生値も使える（`[判定:アイデア]`・`[判定:幸運]`・`[判定:CON×5]` など）。lint は能力値と派生値の名前も技能として通す。

## 新しいシステムが増えたら

`verify.drift.unknownSystems` に出る。次をしてから、そのシステムでサンプルを書く。

1. `scripts/sample-kit/kit.js` の `KNOWN_SYSTEMS` に足す。
2. このファイルの早見表に列を足し、節を1つ書く。
3. 固有の記法があれば、`FEATURES` に `systems: ['<id>']` 付きで足し、[features.md](features.md) にも行を足す。
