# シナリオとしての完成度を上げる書き方

サンプルは「GMが今夜そのまま回せる」ことを目指す。ここにあるのは、そのための考え方と、書いたあとに見直す観点である。
記法の書き方そのものは `docs/01_要件定義書.html` §4、機能ごとの見せ方は `scripts/sample-kit/features.md` にある。

## 目次

1. 骨格（真相・目的・導入・調査・転換・クライマックス・結末）
2. 手がかりの設計
3. 判定の設計
4. NPC
5. HOと見せ場（エモクロア）／探索者の動機（CoC）
6. 文章の種類ごとの書き分け

## 1. 骨格

GMがシナリオを読んで最初に知りたいのは「何が起きていて、プレイヤーに何をさせればよいか」である。DL/KP向けの章の冒頭で、次を言い切る。

- **真相**: 何が起きたのか、なぜ今なのか。怪異・神話存在の動機まで書く。動機が無いと、GMはアドリブの判断ができない。
- **目的**: プレイヤーが何をすれば終わるのかを1〜2文で。「謎を解く」ではなく「誰に何を届ける」「何をどこへ戻す」まで具体的に。
- **流れ**: 場面のつながり（`[場面図]`）と、分岐の条件。
- **進行の目安**: 場面ごとの時間配分と、時間が足りないときに省ける場面。

場面の並びは、次の型を出発点にする。型どおりである必要は無いが、外すなら理由を持つ。

| 段階 | 役割 | 書き落としやすいもの |
|---|---|---|
| 導入 | 探索者／共鳴者が**この事件に関わる理由**を作る | 「なぜ彼らなのか」。偶然の巻き込まれだけにしない |
| 調査 | 手がかりを集め、真相の輪郭に近づく | 場所ごとの手がかりの役割（§2） |
| 転換（幕間） | プレイヤーが動かなくても状況が動く。賭け金が上がる | 時間制限や、誰かが危険にさらされる出来事 |
| クライマックス | **選択**をさせる。戦闘だけで終わらせない | 選択肢ごとの代償 |
| 結末 | 選択の結果を見せ、感情に区切りをつける | 失敗したときの結末も、物語として閉じる |

## 2. 手がかりの設計

- **結論ごとに、手がかりを3つ以上・2か所以上に置く。** 1つの判定の成否に、シナリオの進行を預けない。プレイヤーは見落とすし、ダイスは外れる。
- 手がかりは「場所 → 分かること → 次に行く場所」の鎖にする。骨子の段階で、鎖が途中で切れていないか表で確かめる（[outline-template.md](../assets/outline-template.md)）。
- 探索一覧（`[探索:場所]`）の項目には、それぞれ小見出し（`##`）を立て、そこで何が分かるかを書く。何も無い項目を混ぜるなら、何も無いことが分かる一文を書く（GMが迷わない）。
- 作中の文書（日記・手紙・新聞記事）は情報（`[情報:題名]`）にして、プレイヤーにそのまま渡せるようにする。

## 3. 判定の設計

- **失敗しても話が止まらないようにする。** 失敗の段には「代わりにどうなるか」を書く（時間がかかる・代償を払う・別の場所で同じことが分かる）。
- **成功の段階に意味を持たせる。** 「効果的成功／スペシャルなら、さらに〇〇も分かる」のように、上の段階には追加の情報や有利を書く。同じ文の言い換えにしない。
- **提示タイプは意味で選ぶ。**
  - 強制: 気づくかどうかを選べない反応（物音、悪寒、正気の揺らぎ）
  - 非提示推奨: 判定していること自体を知らせたくないもの（嘘に気づく心理学など）
  - 提示推奨: 通常の調べもの
- 結果が長くなるときは、結果の段を複数行にする（次の `-` までが1項目）。
- 技能名は、そのシステムの技能一覧の名前を使う（`system` 工程で確かめる）。

## 4. NPC

- 主要なNPCには**望み・恐れ・秘密**を1つずつ持たせ、メモに書く。GMはここを見てアドリブで演じる。
- **口調をNPCごとに変える。** 語尾・一人称・文の長さで、名前を伏せても誰か分かるくらいに。主要なセリフの例をメモに残す。
- セリフの備考（`[セリフ:名前/備考]`）には、表情・しぐさ・声の調子を書く。GMが演じる手がかりになる。
- 初めて出てくる場面で NPCカード（`[NPC:名前]`）を出す。あとの場面では、セリフの段落の右に小さなカードが自動で出る。
- 怪異・神話存在もNPCとして登録してよい。能力値とメモ（正体・能力・消える条件）を書いておくと、クライマックスでGMが迷わない。

## 5. HOと見せ場／探索者の動機

**エモクロア:**
- HOごとに、真相とつながった**個人的な事情**を持たせる（記憶を失っている、関係者の家族であるなど）。
- 各HOに、そのHOでなければ果たせない見せ場を少なくとも1つ作る。共鳴判定は、そのHOの事情と結びつく場面に置く。
- HOの情報は、公開対象をそのHOに絞った情報にする。

**CoC:**
- 探索者の作成の条件（関係・職業の向き不向き・継続探索者の扱い）を基本情報に書く。
- 「なぜ探索を続けるのか」をNPCとの関係で作る（友人が危ない、依頼人が戻ってこない）。
- SANチェックは、恐怖の大きさに合わせて値を段階的に上げる。最大のものはクライマックスに取っておく。

## 6. 文章の種類ごとの書き分け

| 種類 | 誰が読むか | 書き方 |
|---|---|---|
| 地の文・GM向け情報（`[DL]`/`[KP]`） | GMが黙読する | 敬体（です・ます）。判断の材料を書く。「PLが〇〇しようとしたら△△」のように、外れたときの扱いも |
| 真相・背景の説明 | GMが黙読する | 常体（である）でよい。事実を時系列で |
| 情景描写（`>`） | GMが読み上げる | 常体。3〜5行。五感（音・匂い・温度）を入れる。**探索者の行動や感情を決めつけない**（「あなたは怖くなった」と書かない） |
| セリフ | GMが演じる | NPCの口調で。説明くさくしない。1つのセリフに情報を詰めすぎない |
| 情報（`[情報:…]`） | プレイヤーが読む | 作中の文書の声で（日記なら日記の文体）。GM向けの注釈を混ぜない |
| TIPS（`>> [TIPS]`） | GMが読む | 進行のコツ・別の回し方・ルールの補足・このエディタの機能の説明。物語の文章は書かない |
| 右の段の地の文（`>> 文`） | GMが読む | BGMの例・小道具・短い補足 |

- 文字色は意味を決めて使う（例: 赤＝危険・重要、青＝手がかり、灰＝補足）。乱用すると何も目立たなくなる。
- 表記をそろえる（数字の全角半角、「〜」と「～」、人名の表記）。

## 7. 長さの配分

長編（11,000字）なら、おおよそ次の配分になる。中編はこれを縮める。

| 部分 | 割合 |
|---|---|
| DL/KP向けの章（真相・流れ・HO・登場人物） | 15% |
| 導入 | 10% |
| 調査 | 45% |
| 転換（幕間） | 10% |
| クライマックス | 10% |
| 結末 | 10% |

字数を満たすために水増ししない。足りないときは、手がかりの鎖・NPCのセリフ・失敗時の扱いなど、GMの役に立つものを足す。

## 8. 配慮と注意事項

- 基本情報の「注意事項」に、扱う描写（死・喪失・暴力・閉鎖的な共同体など）を書く。レベル表示でロスト率や描写の強さを示す。
- 実在の人物・団体・事件は扱わない。地名は架空にする（実在の地方を舞台にするのはよい）。
- 差別や特定の集団への偏見を、物語の仕掛けに使わない。

## 9. 独自性（書き写さない）

- ルールブック・サプリメントの文章・データ（怪物や神格の能力値、呪文、公式のNPC・シナリオ、表）を書き写さない。
- 怪異・神話存在は自作する。エモクロアの怪異は伝承をもとに作ってよい（実在の民話・伝承は使える）。CoC は神話の雰囲気に寄せた独自の存在にする。
- 既存のサンプルと、舞台・怪異・結末の型が重ならないようにする。

## 10. 書いたあとの見直し

GMの目で読ませる前に、自分でも次を確かめる。

- [ ] 真相と目的が、DL/KP向けの章の冒頭で言い切られている
- [ ] 結論ごとに手がかりが3つ以上・2か所以上ある
- [ ] どの判定に失敗しても、先へ進む道がある
- [ ] 各HO（各探索者）に見せ場がある
- [ ] 転換の場面で、プレイヤーが動かなくても状況が動く
- [ ] クライマックスに選択があり、選択ごとの結末が書いてある
- [ ] エンディングの条件が、GMに分かる形で書いてある
- [ ] 情景描写が探索者の行動・感情を決めつけていない
- [ ] NPCの口調が書き分けられている
- [ ] 時間配分の目安と、省ける場面が書いてある
