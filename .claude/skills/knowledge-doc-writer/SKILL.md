# knowledge/ への資料追加

## docs/ との違い

| | 置くもの |
|---|---|
| `docs/` | **このプロジェクト自体**の仕様・設計・運用方針 |
| `knowledge/` | **外部の知識** — 外部ツールの仕様、調査結果、ドメイン知識、ゲームルール等 |

迷ったら「このプロジェクトを作らなければ存在しない情報か」で判断する。
そうなら `docs/`、そうでないなら `knowledge/`。
`knowledge/` から `docs/` への「格上げ」は稀。基本的に独立したナレッジベースとして扱う。

## 手順

1. **下書き**
   内容を `.md` で自由な形式で下書きする。この時点では構造化を気にしない。

2. **配置先を決める**
   - ドメイン・システム別のフォルダを主軸にする（無ければ新設）
   - 外部ツールのエクスポート形式などの**生データサンプルは `external-tool-formats/`**
     に置き、**HTML化しない**（json/txt等のネイティブ形式のまま保持し、解説用HTMLから
     相対リンクで参照する）。整形すると原本としての価値が失われるため。
   - 特定ドメインに紐づかない汎用資料は `general/`

3. **HTML化（機械変換は使わない）**
   `doc-html-writer` スキルと同じコンポーネント群を使う。`docs/assets/style.css` を
   相対パスで参照する（**CSSは複製しない**）。

   markdown-it 等の機械的変換ツールは使わない。`.md` 原稿は書式のばらつきが大きく、
   どの意味づけコンポーネントに当てはめるかは内容を読んだ判断が必要なため、
   必ずエージェントが読んで手作業で変換する。

4. **`.md` 原稿を削除する**
   HTML化が完了したら削除する。二重管理はしない。

5. **`knowledge/INDEX.html` を更新する（同一コミット必須）**
   追加したファイルへのリンクを該当セクションの `card-grid` に追加する。
   フォルダを新設した場合はフォルダ構成の記述も更新する。

   `devenv.config.json` の `knowledge-index-sync` ルールが更新漏れをブロックするため、
   コミット前に必ず確認する。

## 注意事項

- `knowledge/` 配下は生データサンプルを除き、最終的に必ずHTML形式で保持する。
- 調査結果を書くときは**出典と調査日**を残す。外部仕様は変わるため、いつ時点の情報かが
  分からない資料は使えない。
