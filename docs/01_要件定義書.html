TRPG SCENARIO EDITOR / 要件定義

要件定義書

Androidタブレットでの執筆作業を円滑に進めるための、個人利用向け「TRPGシナリオ執筆エディタ」が何を満たすべきかを定める。エモクロアTRPGのシナリオ執筆・NPC管理・保存の安定性・PDF出力に特化する。

この文書の §1 と §2.1 は現行方針と食い違っている。 2026-08-31 に、Google Apps Script + スプレッドシートによるクラウド保存から localStorage への一本化へ移行することを決定した。端末間のデータ移動は JSON のエクスポート／インポートで行い、公開先は GitHub Pages とする。 移行作業の完了時にこの文書を更新すること。決定の経緯は CLAUDE.md の「注意事項」にある。

1. システム構成・動作環境

個人での利用および共有の容易さを考慮し、Google Apps Script (GAS) と Google スプレッドシートをベースとした Webアプリケーションとして構築する。

項目仕様
プラットフォームWebアプリケーション（Google Apps Script Web App として公開）
想定クライアントAndroidタブレット（Google Chrome などのモバイルブラウザ）
データベースGoogle スプレッドシート（シナリオデータ、NPCデータの永続化）
ファイル保存先Google ドライブ（画像アセットやバックアップHTML等の保存用）
上記のうちデータベースとファイル保存先は移行対象。移行後はシナリオ・NPCデータともに ブラウザの localStorage に保存し、Googleドライブは使用しない。 想定クライアントがAndroidタブレットである点は変わらない。

2. 機能要件

2.1 シナリオ管理機能

複数のシナリオをクラウド上で管理できるようにする。

  • シナリオ一覧表示 — 保存済みのシナリオタイトル一覧を表示し、選択して編集を開始できる。
  • 新規シナリオ作成 — 新しいシナリオを作成し、タイトルを決定してエディタを開く。
  • シナリオ削除 — 不要になったシナリオを一覧およびスプレッドシートから削除する。
  • クラウド保存（手動） — 「クラウドに保存」ボタンで、現在編集中のデータをGoogleスプレッドシートに書き込む。
移行後、保存先はスプレッドシートではなく localStorage になり、UI文言も「クラウド保存」から変更される。 加えて端末間のデータ移動のためのJSONエクスポート／インポート機能が要件に追加される。

2.2 シナリオエディタ機能（Markdown入力 ＆ プレビュー）

キーボード入力とタッチ操作のハイブリッドで執筆できる快適なエディタを提供する。

  • Markdownテキストエリア — 左側に広いテキスト入力エリアを配置し、標準的なMarkdownおよび独自拡張記法で執筆する。
  • リアルタイムプレビュー — 執筆中のテキストを解析し、左右2カラムのプレビュー（HTMLレンダリング）をリアルタイム表示する。
  • サイドカラム紐付け（>> 記法）
    • 行または段落内で >> を使用して右側のテキストを記述する。
    • レンダリング時、メイン（左）とサイド（右）が同じ行高さでペアとして表示され、サイドビューが上に詰まる問題を回避する。
  • ローカル自動保存（LocalStorage）
    • 執筆中、キー入力などのタイミングでブラウザの LocalStorage に即座に自動保存する。
    • 通信切断やタブレットの予期せぬシャットダウンから執筆データを保護する。

2.3 執筆アシスタントパネル（タッチ操作支援）

キーボードを接続していない、タブレットのタッチ操作のみの環境でも円滑に執筆できるようにする。

  • テンプレートワンタップ挿入 — 「情景描写」「DL情報」「TIPS/補足」等のボタンを配置し、タップするとカーソル位置に 対応するMarkdownタグ（> や 📋 など）が自動挿入される。
  • エモクロアTRPG専用・入力支援ダイアログ
    • [🎲 技能判定] — エモクロアの標準技能（〈観察眼〉〈心理〉など）のリストから技能を選択すると、対応する判定Markdownテンプレートが自動挿入される。
    • [🌀 共鳴判定] — 「強度」「上昇値」「共鳴感情（感情候補リストから選択可能）」を入力すると [共鳴:強度/上昇/感情] が自動挿入される。

2.4 NPC管理機能

シナリオに登場するNPCの情報をエディタと紐付けて管理する。

  • NPCシート登録 — 各シナリオに紐づくNPCを複数登録できる。
  • 管理項目
    • NPC名、肩書き／属性
    • 能力値・ステータス（HP、MP、共鳴度など）
    • 技能（NPCが所持している技能）
    • メモ・設定（プロフィール、セリフ例、立ち絵画像URLなど）
  • データ連動 — NPCデータはシナリオデータと共にGoogleスプレッドシートに永続化される。

2.5 PDF出力機能

印刷用のCSSを最適化し、執筆したシナリオを美しいレイアウトのままPDF化する。

  • 印刷用プレビュー生成 — 入力フォームやアシスタントパネルなどの不要なUIを排除した、シナリオ本文のみの印刷用プレビューを別ウィンドウで生成する。
  • ブラウザ印刷機能の呼び出し — window.print() を起動し、Androidタブレット標準の印刷メニュー（「PDFとして保存」）へシームレスに繋げる。
  • 印刷スタイル（@media print） — 2カラムのグリッドレイアウト、見出し、各種バッジ（成功度など）の色彩やフォント（明朝体・ゴシック体の使い分け）が崩れないよう最適化した印刷用CSSを適用する。

5. 非機能要件

  • レスポンシブ／モバイルファースト — Androidタブレット（横向き・縦向き）に最適化し、ボタンのサイズは最小でも 44px × 44px を確保してタップミスを防ぐ。
  • オフライン・低通信状態への耐性
    • GASへの保存APIリクエストに失敗した場合でも、LocalStorageに最新データが残るため、通信復帰時に再試行できる仕組みにする。
    • スプレッドシート保存処理中はインジケータ（「保存中…」など）を表示し、誤って画面を閉じるのを防ぐ。
オフライン耐性は、localStorage への一本化によってそもそも通信を伴わなくなるため自然に満たされる。 移行後に残る課題は通信ではなくlocalStorage の容量上限（おおむね5MB）である。 NPCのアバター画像を base64 で保持しているため上限に達しやすい点に注意すること。
