TRPG SCENARIO EDITOR / 要件定義

要件定義書

Androidタブレットでの執筆作業を円滑に進めるための、個人利用向け「TRPGシナリオ執筆エディタ」が何を満たすべきかを定める。エモクロアTRPGのシナリオ執筆・NPC管理・保存の安定性・PDF出力に特化する。

2026-08-31: 保存方式の移行を完了し、本文を更新した。 Google Apps Script + スプレッドシートによるクラウド保存を撤去し、 ブラウザ内への一本化を完了している。端末間のデータ移動は JSONのエクスポート／インポートで行う。公開先は GitHub Pages。 移行前の記述は git の履歴から辿れる。

1. システム構成・動作環境

個人での利用と配布の容易さを最優先し、index.html 1枚で完結する静的Webアプリケーション として構築する。サーバーを持たず、ビルド工程も依存パッケージも無い。

項目仕様
プラットフォーム静的Webアプリケーション（index.html 1枚。GitHub Pages で配信）
想定クライアントAndroidタブレット（Google Chrome などのモバイルブラウザ）
データの保存先ブラウザの IndexedDB（シナリオ本文・NPCデータ・立ち絵）。設定のみ localStorage。保存方式設計書 を参照
端末間のデータ移動JSONファイルの書き出し／読み込み（利用者が手動で持ち運ぶ）
データは端末ごとに独立している。 保存領域はブラウザ・端末ごとに別々であり、同じURLを開いても別の端末では別のデータが見える。 複数の端末で同じシナリオを扱うには、JSONの書き出しと読み込みで明示的に移す必要がある（§2.1）。

またブラウザのサイトデータを消すと保存内容も消える。定期的な書き出しを勧めること。

2. 機能要件

2.1 シナリオ管理機能

複数のシナリオをこの端末内で管理できるようにする。

  • シナリオ一覧表示 — 保存済みのシナリオタイトル一覧を表示し、選択して編集を開始できる。
  • 新規シナリオ作成 — 新しいシナリオを作成し、タイトルを決定してエディタを開く。
  • シナリオ削除 — 不要になったシナリオを一覧および保存領域から削除する。
  • 保存（手動） — 「💾 保存」ボタン（Ctrl+S）で、編集中のデータをシナリオ一覧に書き込む。
  • JSONの書き出し — 全シナリオを1つのファイルに、または1シナリオ単位で書き出す。バックアップと端末間移動を兼ねる。
  • JSONの読み込み — 書き出したファイルを読み込む。既存のシナリオは残し、IDが一致するものだけを上書きする。
自動保存と手動保存は別物である。 入力のたびに走る自動保存は「編集中の作業状態」を保持するだけで、シナリオ一覧には現れない。 一覧に載せるには「💾 保存」を押す必要がある。 ここを取り違えると「保存したのに一覧に出ない」という不具合報告を生む。
読み込みはマージのみとし、保存領域の全置換は用意しない。 ファイル1つの選択ミスで全データを失う操作を、そもそも起こせないようにするため。 不要なシナリオは一覧から個別に削除する。

2.2 シナリオエディタ機能（Markdown入力 ＆ プレビュー）

キーボード入力とタッチ操作のハイブリッドで執筆できる快適なエディタを提供する。

  • Markdownテキストエリア — 左側に広いテキスト入力エリアを配置し、標準的なMarkdownおよび独自拡張記法で執筆する。
  • リアルタイムプレビュー — 執筆中のテキストを解析し、左右2カラムのプレビュー（HTMLレンダリング）をリアルタイム表示する。
  • サイドカラム紐付け（>> 記法）
    • 行または段落内で >> を使用して右側のテキストを記述する。
    • レンダリング時、メイン（左）とサイド（右）が同じ行高さでペアとして表示され、サイドビューが上に詰まる問題を回避する。
  • ローカル自動保存（LocalStorage）
    • 執筆中、キー入力などのタイミングでブラウザの LocalStorage に即座に自動保存する。
    • 通信切断やタブレットの予期せぬシャットダウンから執筆データを保護する。

2.3 執筆アシスタントパネル（タッチ操作支援）

キーボードを接続していない、タブレットのタッチ操作のみの環境でも円滑に執筆できるようにする。

  • テンプレートワンタップ挿入 — 「情景描写」「DL情報／KP情報」「TIPS/補足」等のボタンを配置し、タップするとカーソル位置に 対応するMarkdownタグ（> や [DL] など）が自動挿入される。 GM向け情報のボタン名と挿入されるタグは、シナリオのゲームシステムに追従する（2.7 参照）。
  • 入力支援ダイアログ
    • [🎲 技能判定]（全システム共通） — 選んだシステムの標準技能リストから技能を選択すると、対応する判定Markdownテンプレートが自動挿入される。画面構成は 3.2 を参照。
    • [🌀 共鳴判定]（エモクロア専用） — 「強度」「上昇値」「共鳴感情（感情候補リストから選択可能）」を入力すると [共鳴:強度/上昇/感情] が自動挿入される。他システムではボタンごと非表示になる。
    • [🧠 SANチェック]（CoC専用・2026-09-01 追加） — 「成功時の減少値」「失敗時の減少値」を入力すると [SAN:成功/失敗] と結果の枠が自動挿入される。よく使う組み合わせ（0/1・1/1D6 など）はワンタップで入る。他システムではボタンごと非表示になる。
    • [🗣 NPCのセリフ]（全システム共通・2026-10-05 追加・Alt+Q） — 登録済みのNPCを一覧から選ぶと（名前・職業で絞り込める）、[セリフ:NPC名] 「」 が挿入され、カーソルが「」の間に置かれる。備考欄（絞り込み欄から Tab で移れる）に「震える声で」のような読み上げ方を書くと、[セリフ:NPC名/備考] になる。備考は Shift+Enter で改行できる（空行は詰める）。NPCが未登録なら、NPC管理を開くボタンを出す。
    • [📄 情報]（全システム共通・2026-10-05 追加・Alt+I） — 情報一覧に登録した情報を選ぶと（題名・公開対象・本文の言葉で絞り込める）、[情報:題名] が挿入される。まだ無い題名を打って Enter を押すと、その場で登録して挿入し、中身を書けるよう情報一覧を開く。詳細は 2.10。
    • [🎨 文字色]（全システム共通・2026-09-01 追加） — エディタで選んだ文字を {赤:…} の形で囲む。6色のパレットと任意のカラーコードを選べる。詳細は 4.3 を参照。
  • パネルの構成（2026-10-05 改訂） — ボタンは分類（構成・本文・判定・資料）ごとにまとめ、アイコンの下に名前を置く。 ショートカットキーはボタン名には書かず、マウスを乗せたときの吹き出しに、何が起きるかの説明と一緒に出す。 幅が足りない画面では、分類名を消し、名前を短くして詰める。1280px幅では正式名のまま、768px幅（タブレット縦）までは横スクロールなしで全ボタンが収まる。
  • [🔎 すべての操作]（コマンドパレット・2026-10-05 追加） — パネル末尾のボタンまたは Ctrl+K で開く。操作の名前（ひらがなの読みでも可）で絞り込み、Enter で実行する。 保存・PDF出力など、パネルに無い操作も含む。各候補の横にショートカットキーが出る。
パネル・コマンドパレット・ショートカット設定は、同じ操作の表から作られる。 ボタンを足すときの手順と、パネルの形を決めた理由は 07 操作の入口設計書 にある。

2.4 NPC管理機能

シナリオに登場するNPCの情報をエディタと紐付けて管理する。

  • NPCシート登録 — 各シナリオに紐づくNPCを複数登録できる。
  • 管理項目
    • NPC名、肩書き／属性
    • 能力値・ステータス（HP、MP、共鳴度など）
    • 技能（NPCが所持している技能）
    • メモ（題名と内容の組を複数。背景・主要セリフ・シナリオ上の役割などを分けて書く）
  • データ連動 — NPCデータはシナリオデータと共に保存され、JSONの書き出し／読み込みにも含まれる。
  • セリフの色（2026-10-05 追加） — NPCごとに色を1つ決められる（基本タブ。文字色と同じパレット6色・なし・マイパレット・任意の色）。 本文の [セリフ:NPC名] の発言がこの色で出る（4.1）。 NPC一覧のアイコンの縁にも同じ色を出す。 セリフは下部パネルの「🗣 NPCのセリフ」（2.3）からも、NPCを選んで挿入できる。 NPC管理の「🗣️ セリフ用タグ」は、このNPCの [セリフ:NPC名] 「」 を挿入する （以前は > 「」 >> [NPC:名前] を挿入していた。既存の本文のその書き方はそのまま表示される）。
  • メモは題名と内容の組で複数持つ（2026-10-05 変更） — 1つの欄に背景もセリフも役割も書き込むと、長くなるほど目的の記述を探せなくなるため。 データは memos: [{ id, title, body }]。 それ以前の memo（1つの文字列）は、中身があれば題名「設定メモ」の1件として引き継ぐ （読み込み時に normalizeNpc() が変換する。保存データ・書き出したJSONのどちらも対象）。 プレビューのNPCカードには題名を小見出しにして1件ずつ並べ、「プロフィールを挿入」では「・題名：内容」の形で1件ずつ並べる。 題名も内容も空のメモはどちらにも出さない。中身のあるメモを削除するときだけ確認を出す。
  • 能力値のレーダーチャート（2026-09-01 追加） — 能力値の偏りを一目で掴めるよう、NPC編集画面とプレビューのNPCカードに図示する。 軸の数・名称・上限はゲームシステムに追従する。 PDF出力にもそのまま載るため、卓上で配る資料としても使える。
  • 技能・感情の入力補助（2026-09-01 追加） — 所持技能と共鳴感情は、技能判定ダイアログと同じ分類ピッカー（3.2）から選べる （NPC管理では普段は畳んでおく。3.3）。
  • 技能名と値は別の欄で入力する（2026-10-05 変更） — ピッカーで選ぶと名前の欄が埋まり、カーソルが値の欄へ移る。 値を空けたまま追加すると、デフォルト値が入る。
    システムデフォルト値理由
    エモクロア Lv1 技能レベルは0〜3で、0は判定できない。「持っている」技能の最低値
    CoC6版 技能一覧の初期値（目星なら25） 「DEX×2」のような式は、そのNPCの能力値が入っていれば計算し、無ければ式のまま入れる（計算されていないことに気づけるように）。 「運転（自動車）」のように（任意）を埋めた名前は「運転」の初期値を使う。 一覧に無い技能は 1（6版で最も多い初期値で、下限として扱える）。
    デフォルト値は値の欄に薄く表示しておく（名前を打つたびに出し直す）。 以前は「初期値を勝手に入れると、直し忘れてそのまま登録される」として値を手入力に任せていたが、 何が入るかを追加前に見せることで、この懸念に手当てしたうえでデフォルト値を入れる形に改めた。 エモクロアでは「2」「lv2」と打っても「Lv2」に揃える。 保存形式は従来どおり「技能名:値」の1文字列で、名前の欄に「観察眼:Lv2」と打っても名前と値に分けて受け付ける。
  • 立ち絵画像（2026-09-01 改善） — 読み込んだ画像は長辺1024pxへ自動縮小してから保存する。 原寸のまま持つと保存領域を無駄に使い、書き出したJSONも肥大するため。 縮小前後の容量を画面に表示し、利用者が容量の余裕を判断できるようにする。

2.5 PDF出力機能

印刷用のCSSを最適化し、執筆したシナリオを美しいレイアウトのままPDF化する。

  • 印刷用プレビュー生成 — 入力フォームやアシスタントパネルなどの不要なUIを排除した、シナリオ本文のみの印刷用プレビューを別ウィンドウで生成する。
  • ブラウザ印刷機能の呼び出し — window.print() を起動し、Androidタブレット標準の印刷メニュー（「PDFとして保存」）へシームレスに繋げる。
  • 印刷スタイル（@media print） — 2カラムのグリッドレイアウト、見出し、各種バッジ（成功度など）の色彩やフォント（明朝体・ゴシック体の使い分け）が崩れないよう最適化した印刷用CSSを適用する。

2.6 モーダルの共通操作（2026-09-01 追加）

すべてのモーダル（シナリオ一覧・技能判定・共鳴判定・NPC管理・ショートカット設定・コマンドパレット）は、以下の3つの方法で閉じられること。

  • × ボタン
  • 背景（モーダルの外側）のクリック — ただし中身の上で押し始めた場合は、指が外に出ても閉じない（テキスト選択のたびに消えるのを防ぐため）
  • Escキー — 複数開いている場合は一番手前のものを閉じる
閉じる経路を増やすのは、閉じられなくなる事故を防ぐためである。 以前は × ボタンだけが閉じる手段で、共鳴判定モーダルはその × が別のモーダルを閉じる関数を呼んでいたため、 一度開くと閉じられなかった（2026-09-01 修正）。 経路が1本しかないと、そこが壊れた時点で画面が操作不能になる。

なお、ショートカットキーの記録中は Esc がその中断に使われるため、モーダルは閉じない。

2.7 ゲームシステムの選択（2026-09-01 追加）

シナリオごとにゲームシステムを1つ持ち、新規作成時に選んで以降は変更できない。 能力値の項目名がシステム間で全く異なり、自動換算ができないため、 途中で切り替えると登録済みNPCの数値が何を指すのか分からなくなるからである。

2.8 リリースノートの閲覧（2026-09-02 追加）

ヘッダー左上のバージョン番号はボタンであり、押すと版ごとの変更点を読める。 最新の版だけを開いた状態で表示し、過去の版は折りたたむ。

  • 載せるのは利用者から見える変更だけ — 内部の整理やドキュメントの更新は載せない
  • ヘッダーのバージョン表記も同じ一覧から描く — 版を上げるときに書き換える場所を1箇所に保つため、HTML側には数字を持たせない
  • アプリ単体で読めること — 配布した相手はリポジトリを持たないため、外部ファイルの読み込みに頼らない
文面の置き場所・版を上げるときの手順・過去の版をどう区切ったかは リリースノート運用書 にある。

2.9 場面ツリー管理（2026-09-08 追加）

場面をカードにして、分岐と合流を樹形図で並べる。 執筆者本人が物語の骨格を見失わないための道具であり、 本文が1本の長いテキストである以上、繋がりは書いている人の頭の中にしか残らない。

  • ヘッダーの「執筆／場面図」で画面を切り替える — 場面図は画面全体を使う
  • カードは本文の # 見出しと名前で対応づける — 本文側に管理用の記号を書かないので、既存のシナリオをそのまま使える
  • 本文の見出しの取り込みは指示したときだけ — 自動では作らず、消しもしない。カードには概要メモ・種別・登場NPCが付くため、勝手に消えると被害が大きい
  • 対応する見出しが無いカードには「⚠ 未執筆」を出す — まだ書いていない場面を先に置けることが、整理の道具として重要
  • カードから本文の該当位置へ飛べる — 折り返しを含めた実際の位置へスクロールし、見出しを選択した状態にする
  • 合流を許す — 「どのルートを通っても最終決戦に至る」を線で表せる。循環は作らせない
  • つなぐのは Ctrl＋ドラッグ — カードから相手へ引く。引いている間に、つながるかどうかと、つながらない理由が出る。指で操作する場合のために、右のペインから選ぶ方法も残す
  • 接続には分岐の条件を書ける — 「【目星】成功」のような短い文を線の上に出す
  • 自動で並べたうえで、手で動かせる — 動かした位置は保存し、「整列」で自動配置に戻せる
  • 本文へ図として出せる — [場面図] で全体、[場面図:場面名] でその場面から先だけ。カードごとに図へ出すかを選べる（§4.5）
データの持ち方・保存先・同期の考え方・却下した案は 場面ツリー設計書 にある。

2.10 プレイヤーへ渡す情報（2026-10-05 追加）

日記・手紙・調べて分かったことなど、セッション中にプレイヤーへ渡す情報を台本に載せ、 チャット（ココフォリアなど）へ簡単にコピーして貼れるようにする。 GMだけが読む [DL]／[KP] とは別物である。

  • 情報は一覧で管理する — 題名・公開対象・本文を、情報一覧（Alt+L、または下部パネルの「資料」グループにある「📑 情報一覧」）で追加・編集・削除する。シナリオと一緒に保存され、JSONの書き出し／読み込みにも含まれる。
  • 本文には参照だけを書く — [情報:題名]。「📄 情報」（下部パネル・Alt+I）で一覧から選んで入れる。まだ無い題名を打てば、その場で登録して入れる。
  • 公開対象は自由入力 — 「全員」「HO1」「目星成功者」など。入力時に「全員」と、そのシナリオで使った対象を候補に出す。新しく作った情報は「未設定」で始まる（赤いバッジ）。
  • コピーは「【題名】」＋本文 — プレビューの情報と一覧の両方にコピーボタンを置く。文字色などの記法は取り除く。ボタンは印刷・PDFには出さない。
  • 題名を変えると本文の参照も書き換わる — 題名は参照のキーなので、空や重複は受け付けない。
  • 一覧は場面ごとにまとめる — 本文で最初に参照している場面（# 見出し）ごとに並べ、参照していない情報は最後にまとめる。題名を押すとプレビューのその情報へ移動する。
  • 一覧の外をクリックすると閉じる — Esc・×・開閉ボタンでも閉じる。
記法の形・データの持ち方・却下した案は 記法設計書 §9 にある。

2.11 シナリオ基本情報（2026-10-05 追加）

シナリオの基本情報（タイトル・サムネイル・概要・プレイ人数・難易度など）を登録し、 プレビューとPDFの先頭に表紙として出す。中身の構成は作者によってさまざまなので、汎用の項目を好きな順に並べる形にする。

  • 入口 — ヘッダーのタイトル欄の隣の「📘 基本情報」、コマンドパレット、Alt+B。下部パネルには置かない（幅が尽きているため）。
  • タイトル — ヘッダーのタイトル欄と同じもの。どちらで変えてもよい。
  • サムネイル — 画像1枚。読み込み時に長辺1600pxへ縮める。
  • 見出しと本文 — 「概要」と本文のような組を、いくつでも足せる。本文には文字色の記法と改行が使える。
  • レベル — 項目名と記号の数の組（例: 難易度 ★★★☆☆）。記号（星・丸・ひし形・四角・ハート・三角）と段階の数（1〜10）を選べる。記号を押して段階を決める（同じ記号をもう一度押すと1つ下がる）。単独でも、見出しの中に本文と混ぜても置ける。
  • 小見出し（2026-10-05 追加） — 見出し（概要・あらすじなど）の中に、小見出しと内容の組（プレイ人数｜2〜3人、想定時間｜3〜4時間など）を置ける。台本では「項目名｜内容」の表になり、並んだレベルと同じ表にまとまる。
  • 並べ替えと削除 — ↑ ↓ で並べ替える。中身のある項目を消すときだけ確認する。
  • テンプレート（2026-10-05 追加） — 見出し・小見出し・レベルの並びと名前に名前を付けて保存し、別のシナリオで「置き換える」か「後ろに足す」で呼び出せる。既定では構成だけを保存し、チェックを入れると本文や値も保存する。タイトルとサムネイルは含まない。この端末の設定として保存する（保存キー trpg_basic_info_templates。30件まで）。
  • 表紙を出さない場合 — タイトルが「無題のシナリオ」のままで、サムネイルも項目も無いとき。
  • 保存 — シナリオと一緒に保存され、JSONの書き出し／読み込みにも含まれる（サムネイルは立ち絵と同じく画像として書き出す）。
項目の形・却下した案・表紙の出し方は シナリオ基本情報設計書 にある。

2.12 巻末：FAQ・あとがき・権利表記（2026-10-05 追加）

台本（プレビューとPDF）の最後に置くものを、本文とは別の入口で書けるようにする。 並びは本文 → FAQ → あとがきなどの節 → 権利表記で、権利表記が一番最後になる。

  • 入口 — ヘッダーの「📕 巻末」（基本情報の隣）。開いた画面のタブで「FAQ」と「あとがき・権利表記」を切り替える。コマンドパレットの「FAQ」（Alt+A）・「あとがき・権利表記」からは、そのタブで開く。下部パネルには置かない。
  • FAQ — シナリオに付ける質問と回答の組（このアプリの使い方のヘルプではない）。追加・編集し、↑ ↓ で並べ替える。質問・回答のどちらかが書いてあるものだけを出し、片方だけのものは「（未入力）」と出す。
  • あとがきなどの節 — 見出しと本文の組を好きなだけ（あとがき・謝辞・クレジット・更新履歴など）。よく使う見出しを入れた状態で足す近道がある。↑ ↓ で並べ替える。
  • 権利表記 — 1つの欄。台本の一番最後に、線で区切って小さめの文字で出る。システムの公式ガイドラインにある定型文はアプリに持たせない（利用者が公式の文面を貼る）。
  • 共通 — 文字色の記法と改行が使える。中身のあるものを消すときだけ確認する。何も書いていなければ台本には何も出ない。シナリオと一緒に保存され、JSONの書き出し／読み込みにも含まれる。
形・並び順・1つの画面にまとめた理由・定型文を持たない理由は 巻末設計書 にある。

2.13 元に戻す・やり直す（2026-10-06 追加）

Ctrl+Z で操作を取り消し、Ctrl+Y（または Ctrl+Shift+Z）でやり直す。押した場所で効き方が変わる。

  • 本文の入力欄の中 — 本文の入力を細かく戻す。打った文字だけでなく、記法のボタンで入れたもの・文字色・情報の題名の変更による書き換えも戻せる。
  • ほかの入力欄の中（NPCの名前・メモなど） — その欄の入力を戻す。
  • 入力欄の外（ボタン・場面図・プレビューなど） — シナリオ全体（本文・NPC・情報・基本情報・巻末・場面図・タイトル）を操作の順に戻す。削除・並べ替え・場面カードの移動も戻せる。削除したNPCは立ち絵ごと戻る。戻したときは、何が戻ったかを画面の下に短く出す。
  • コマンドパレットの「元に戻す」「やり直す」からも使える（キーボードの無いタブレット向け）。
  • 戻せるのは100回まで。シナリオを開く・新しく作ると、それまでの履歴は消える。
2段構えにした理由・履歴の仕組みは 元に戻す設計書 にある。

成功度の枠と、利用者が足す「自由枠」（2026-09-01 追加）

チェックした枠だけが - キーワード: の行として生成される。 枠の顔ぶれと既定のチェックはシステム定義（rollTiers）から作るが、 それだけでは足りない場合に、利用者が任意の名称の枠を足せる。 「幸運での回避」「情報の一部のみ」のように、 ルール上の成功段階ではないがシナリオ上は分岐させたい結果があるため。

  • 自由枠はシステムごとに分けて持つ。成功段階の考え方がシステムで違うため。
  • シナリオ本体ではなくこの端末の設定として保存する（保存キー trpg_custom_tiers。ショートカット設定と同じ扱い）。 シナリオごとに持たせると、同じ枠を使うたびに作り直すことになるため。

  • 上限は12件。際限なく増えるとチェックボックスの一覧が判読できなくなるため。

4.2 技能判定ブロックの構造化

技能判定ブロックは、複数行の判定結果バッジに対応する。

[判定:技能名]
- キーワード: 結果テキスト

結果テキストの改行（2026-09-01 追加）

- で始まらない行は、直前の結果テキストの続きとして連結され、 プレビューでは改行して表示される。1つの結果に手順や補足を書き足せる。 

[判定:目星]
- 成功: 引き出しの奥に鍵を見つける。
  鍵には「B-3」と刻印がある。
- 失敗: 何も見つからない。
判定ブロックの終わりには空行を置くこと。 段落は空行で区切られるため、空行を置かずに本文を続けると、 その本文が最後の結果行の続きとして箱の中に取り込まれる。

この改修より前は - で始まらない行を読み飛ばしていた（＝書いても表示されなかった）。 そのため古いシナリオにこの書き方が残っている可能性がある。 表示が変わるのは「消えていた文字が出るようになる」方向だけで、既存の表示が失われることはない。

4.3 インライン装飾：文字色（2026-09-01 追加）

文中の一部だけを着色する。ブロック記法が [ ] を使うのに対し、 インライン装飾は { } を使って系統を分けている。 

扉の奥から{赤:低い唸り声}が聞こえる。
{#88ccff:淡い光}が漏れている。

{青:…}青 #2563ebic-blue
{緑:…}緑 #059669ic-green

加えて {#rrggbb:…} / {#rgb:…} の形で任意の色を指定できる。 ただし淡い色はPDFにすると読めなくなるため、既定ではパレットを使う。 使い分けの根拠は 記法設計書 §3 にある。

マイパレット（2026-10-05 追加）— よく使う任意の色を登録しておき、次から1回で選べる。 文字色の画面では「任意の色」で色を選んで「＋ マイパレットに登録」、NPC管理のセリフの色では「＋ 今の色を登録」で登録する。 一覧は両方で共通で、登録した色を押すと、文字色では {#rrggbb:…} で囲み、NPCではその色をセリフの色にする。 「整理」を押してから色を押すと削除できる。シナリオではなくこの端末の設定として保存する（保存キー trpg_my_palette。24色まで）。 固定パレットと同じ色・登録済みの色は登録しない。設計は 記法設計書 §3.6。

使える場所

通常文章・情景描写・GM向け情報・TIPS/補足・判定ブロックの結果テキスト・探索一覧の各項目・ シーン見出し・探索小見出し・NPCのセリフの発言・NPCカードのメモ欄で使える。 コロンは半角 : と全角 ： のどちらでもよい。

色名でも16進でもないものは記法として扱わず、原文のまま表示される。 {注:これは色ではない} はそのまま出る。 本文に波括弧を書くこと自体は珍しくないため、取りこぼしより誤変換を避ける側に倒している。
色記法は1行に閉じる。入れ子にはできない。 中身に改行や波括弧を含められないため、{赤:{青:…}} と書くと 外側が解釈されず波括弧が本文に出る。 🎨文字色ボタンは、色の付いた文字を選んで別の色を押すと入れ子ではなく付け替えになる。

4.4 SANチェックブロック（2026-09-01 追加）

クトゥルフ神話TRPGの正気度チェック。技能判定ブロックと同じ構造を持ち、 ヘッダに減少値、その下に成否ごとの結果テキストを書く。 

[SAN:成功時の減少値/失敗時の減少値]
- キーワード: 結果テキスト
[SAN:1/1D6]
- 成功: 一瞬たじろぐが正気を保つ。
- 失敗: 記憶が飛ぶ。
  以降このシーンでは【聞き耳】に-20。

プレビューでは <div class="roll-box san-box"> として、 技能判定と同じ骨格・赤系の配色で描画され、ヘッダの右に 「成功 1 / 失敗 1D6」のバッジが出る。 結果テキストは技能判定と同じくバッジ化され、4.2 の改行にも対応する。 キーワードの対応表は 4.2 のCoC 6版の表と共通である。

減少値を省略した場合は 成功 0 / 失敗 1D3 として扱う。 [san:…] のように小文字でも認識される。 この記法はエモクロアのシナリオでも解釈される（挿入ボタンが出ないだけ）。

5. 非機能要件

  • レスポンシブ／モバイルファースト — Androidタブレット（横向き・縦向き）に最適化し、ボタンのサイズは最小でも 44px × 44px を確保してタップミスを防ぐ。
  • 完全なオフライン動作
    • 保存に通信を伴わないため、電波の無い会場や機内モードでも支障なく執筆できる。
    • ネットワークを使うのは Google Fonts の読み込みのみ。読み込めない場合も代替フォントで動作する。
  • 保存容量の上限への対応
    • 保存領域の上限を超えた場合、保存が黙って失敗しないよう、書き出しを促すメッセージを表示する。 上限そのものは IndexedDB への移行で大幅に緩和した（保存方式設計書）。
    • NPCのアバター画像を base64 で保持しているため容量を大きく消費する。上限に達する主因はこれである。
