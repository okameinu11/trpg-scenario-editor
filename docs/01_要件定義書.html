TRPG SCENARIO EDITOR / 要件定義

要件定義書

Androidタブレットでの執筆作業を円滑に進めるための、個人利用向け「TRPGシナリオ執筆エディタ」が何を満たすべきかを定める。エモクロアTRPGのシナリオ執筆・NPC管理・保存の安定性・PDF出力に特化する。

2026-08-31: 保存方式の移行を完了し、本文を更新した。 Google Apps Script + スプレッドシートによるクラウド保存を撤去し、 ブラウザ内への一本化を完了している。端末間のデータ移動は JSONのエクスポート／インポートで行う。公開先は GitHub Pages。 移行前の記述は git の履歴から辿れる。

1. システム構成・動作環境

個人での利用と配布の容易さを最優先し、index.html 1枚で完結する静的Webアプリケーション として構築する。サーバーを持たず、ビルド工程も依存パッケージも無い。

項目仕様
プラットフォーム静的Webアプリケーション（index.html 1枚。GitHub Pages で配信）
想定クライアントAndroidタブレット（Google Chrome などのモバイルブラウザ）
データの保存先ブラウザの IndexedDB（シナリオ本文・NPCデータ・立ち絵）。設定のみ localStorage。保存方式設計書 を参照
端末間のデータ移動JSONファイルの書き出し／読み込み（利用者が手動で持ち運ぶ）
データは端末ごとに独立している。 保存領域はブラウザ・端末ごとに別々であり、同じURLを開いても別の端末では別のデータが見える。 複数の端末で同じシナリオを扱うには、JSONの書き出しと読み込みで明示的に移す必要がある（§2.1）。

またブラウザのサイトデータを消すと保存内容も消える。定期的な書き出しを勧めること。

2. 機能要件

2.1 シナリオ管理機能

複数のシナリオをこの端末内で管理できるようにする。

  • シナリオ一覧表示 — 保存済みのシナリオタイトル一覧を表示し、選択して編集を開始できる。
  • 新規シナリオ作成 — 新しいシナリオを作成し、タイトルを決定してエディタを開く。
  • シナリオ削除 — 不要になったシナリオを一覧および保存領域から削除する。
  • 保存（手動） — 「💾 保存」ボタン（Ctrl+S）で、編集中のデータをシナリオ一覧に書き込む。
  • JSONの書き出し — 全シナリオを1つのファイルに、または1シナリオ単位で書き出す。バックアップと端末間移動を兼ねる。
  • JSONの読み込み — 書き出したファイルを読み込む。既存のシナリオは残し、IDが一致するものだけを上書きする。
自動保存と手動保存は別物である。 入力のたびに走る自動保存は「編集中の作業状態」を保持するだけで、シナリオ一覧には現れない。 一覧に載せるには「💾 保存」を押す必要がある。 ここを取り違えると「保存したのに一覧に出ない」という不具合報告を生む。
読み込みはマージのみとし、保存領域の全置換は用意しない。 ファイル1つの選択ミスで全データを失う操作を、そもそも起こせないようにするため。 不要なシナリオは一覧から個別に削除する。

2.2 シナリオエディタ機能（Markdown入力 ＆ プレビュー）

キーボード入力とタッチ操作のハイブリッドで執筆できる快適なエディタを提供する。

  • Markdownテキストエリア — 左側に広いテキスト入力エリアを配置し、標準的なMarkdownおよび独自拡張記法で執筆する。
  • リアルタイムプレビュー — 執筆中のテキストを解析し、左右2カラムのプレビュー（HTMLレンダリング）をリアルタイム表示する。
  • サイドカラム紐付け（>> 記法）
    • 行または段落内で >> を使用して右側のテキストを記述する。
    • レンダリング時、メイン（左）とサイド（右）が同じ行高さでペアとして表示され、サイドビューが上に詰まる問題を回避する。
  • ローカル自動保存（LocalStorage）
    • 執筆中、キー入力などのタイミングでブラウザの LocalStorage に即座に自動保存する。
    • 通信切断やタブレットの予期せぬシャットダウンから執筆データを保護する。

2.3 執筆アシスタントパネル（タッチ操作支援）

キーボードを接続していない、タブレットのタッチ操作のみの環境でも円滑に執筆できるようにする。

  • テンプレートワンタップ挿入 — 「情景描写」「DL情報／KP情報」「TIPS/補足」等のボタンを配置し、タップするとカーソル位置に 対応するMarkdownタグ（> や [DL] など）が自動挿入される。 GM向け情報のボタン名と挿入されるタグは、シナリオのゲームシステムに追従する（2.7 参照）。
  • 入力支援ダイアログ
    • [🎲 技能判定]（全システム共通） — 選んだシステムの標準技能リストから技能を選択すると、対応する判定Markdownテンプレートが自動挿入される。画面構成は 3.2 を参照。
    • [🌀 共鳴判定]（エモクロア専用） — 「強度」「上昇値」「共鳴感情（感情候補リストから選択可能）」を入力すると [共鳴:強度/上昇/感情] が自動挿入される。他システムではボタンごと非表示になる。

2.4 NPC管理機能

シナリオに登場するNPCの情報をエディタと紐付けて管理する。

  • NPCシート登録 — 各シナリオに紐づくNPCを複数登録できる。
  • 管理項目
    • NPC名、肩書き／属性
    • 能力値・ステータス（HP、MP、共鳴度など）
    • 技能（NPCが所持している技能）
    • メモ・設定（プロフィール、セリフ例、立ち絵画像URLなど）
  • データ連動 — NPCデータはシナリオデータと共に保存され、JSONの書き出し／読み込みにも含まれる。
  • 能力値のレーダーチャート（2026-09-01 追加） — 能力値の偏りを一目で掴めるよう、NPC編集画面とプレビューのNPCカードに図示する。 軸の数・名称・上限はゲームシステムに追従する。 PDF出力にもそのまま載るため、卓上で配る資料としても使える。
  • 技能・感情の入力補助（2026-09-01 追加） — 所持技能と共鳴感情は、技能判定ダイアログと同じ分類ピッカー（3.2）から選べる。 技能の値は「技能名:Lv2」「技能名:45」の形なので、ピッカーは名前だけを入力欄へ入れ、 レベルや初期値は手で足す。初期値を勝手に入れると、直し忘れてそのまま登録されるため。
  • 立ち絵画像（2026-09-01 改善） — 読み込んだ画像は長辺1024pxへ自動縮小してから保存する。 原寸のまま持つと保存領域を無駄に使い、書き出したJSONも肥大するため。 縮小前後の容量を画面に表示し、利用者が容量の余裕を判断できるようにする。

2.5 PDF出力機能

印刷用のCSSを最適化し、執筆したシナリオを美しいレイアウトのままPDF化する。

  • 印刷用プレビュー生成 — 入力フォームやアシスタントパネルなどの不要なUIを排除した、シナリオ本文のみの印刷用プレビューを別ウィンドウで生成する。
  • ブラウザ印刷機能の呼び出し — window.print() を起動し、Androidタブレット標準の印刷メニュー（「PDFとして保存」）へシームレスに繋げる。
  • 印刷スタイル（@media print） — 2カラムのグリッドレイアウト、見出し、各種バッジ（成功度など）の色彩やフォント（明朝体・ゴシック体の使い分け）が崩れないよう最適化した印刷用CSSを適用する。

2.6 モーダルの共通操作（2026-09-01 追加）

すべてのモーダル（シナリオ一覧・技能判定・共鳴判定・NPC管理・ショートカット設定）は、以下の3つの方法で閉じられること。

  • × ボタン
  • 背景（モーダルの外側）のクリック — ただし中身の上で押し始めた場合は、指が外に出ても閉じない（テキスト選択のたびに消えるのを防ぐため）
  • Escキー — 複数開いている場合は一番手前のものを閉じる
閉じる経路を増やすのは、閉じられなくなる事故を防ぐためである。 以前は × ボタンだけが閉じる手段で、共鳴判定モーダルはその × が別のモーダルを閉じる関数を呼んでいたため、 一度開くと閉じられなかった（2026-09-01 修正）。 経路が1本しかないと、そこが壊れた時点で画面が操作不能になる。

なお、ショートカットキーの記録中は Esc がその中断に使われるため、モーダルは閉じない。

2.7 ゲームシステムの選択（2026-09-01 追加）

シナリオごとにゲームシステムを1つ持ち、新規作成時に選んで以降は変更できない。 能力値の項目名がシステム間で全く異なり、自動換算ができないため、 途中で切り替えると登録済みNPCの数値が何を指すのか分からなくなるからである。

システムを持たない既存シナリオは、すべてエモクロアとして扱う。 この機能より前に保存されたデータや、未知のシステムIDが入ってきた場合も同様。 利用者が何もしなくても従来どおり開ける。
GM向け情報の記法は、どのシステムでも [DL] と [KP] の両方を受け付ける。 挿入ボタンが出すタグとプレビューの見出しだけがシステムに追従する。 片方しか解釈しないと、他システムで書かれた本文を貼り付けたときや、 GMが慣れた呼称で手打ちしたときに、その段落が装飾されないまま素通ししてしまうため。
派生値は能力値がすべて入力されたときだけ自動計算する。 未入力のうちに計算して書き込むと、利用者が手で入れた値を消してしまうため。 自動計算された値は手で上書きできる（NPCは必ずしもルールどおりの数値とは限らないため）。

3.2 分類ピッカー（技能・感情の共通部品）（2026-09-01 追加）

技能の分類数・件数はシステムによって大きく変わる（エモクロア7分類／CoC6版5分類、 1分類あたり20件を超えることもある）。横並びのタブと1枚のグリッドでは、 分類を探すのに横スクロール、技能を探すのに縦スクロールが要り、現在地を見失いやすかった。 そこで左に分類、右に候補を置き、スクロールの向きを縦だけに揃える。

この部品は「分類 → 候補」を選ばせる箇所すべてで共通に使う。 以前は技能判定と共鳴感情でUIも実装も別物だった。 片方だけ直して他方が取り残される事故を避けるため、1つの部品に集約している。

成功度の枠と、利用者が足す「自由枠」（2026-09-01 追加）

チェックした枠だけが - キーワード: の行として生成される。 枠の顔ぶれと既定のチェックはシステム定義（rollTiers）から作るが、 それだけでは足りない場合に、利用者が任意の名称の枠を足せる。 「幸運での回避」「情報の一部のみ」のように、 ルール上の成功段階ではないがシナリオ上は分岐させたい結果があるため。

  • 自由枠はシステムごとに分けて持つ。成功段階の考え方がシステムで違うため。
  • シナリオ本体ではなくこの端末の設定として保存する（保存キー trpg_custom_tiers。ショートカット設定と同じ扱い）。 シナリオごとに持たせると、同じ枠を使うたびに作り直すことになるため。
  • 同名の枠は追加できない。生成される行もチェックボックスも見分けが付かなくなるため。
  • 上限は12件。際限なく増えるとチェックボックスの一覧が判読できなくなるため。

3.3 NPC管理ダイアログのレイアウト（2026-09-01 変更）

NPCの入力項目はシステムによって数が変わる（派生値はエモクロア3件・CoC6版7件）。 横幅800pxのダイアログでは編集エリアが実質500px程度しかなく、 ラベルやプレースホルダーが折り返して欄の高さがずれていた。 ダイアログを1040pxへ広げ、崩れていた箇所を作り直した。

  • プロフィールは1行に集約 — NPC名・年齢・性別・職業。 以前は職業だけ次の行にあり、立ち絵と横並びで幅を取り合っていた。
  • 立ち絵画像は独立した行 — プレビュー・操作ボタン・注記を横に並べる幅を確保する。 以前は行の半分しか使えず、「保存時に長辺1024pxへ自動縮小されます」が折り返していた。
  • 派生値はレーダーチャートの左（能力値の下）へ移した — チャートと縦の丈が釣り合い、右下に大きな余白が残らない。 カラム数は幅なりに決める（auto-fit）。4カラム固定では 「マジック・ポイント (MP)」「ダメージ・ボーナス」のラベルが折り返し、 同じ行の入力欄だけが下にずれていた。
  • 入力欄はラベルが折り返しても行内で高さを揃える （.status-grid-8 .form-group に justify-content: space-between）。
縦画面（768px以下）では縦積みにする。 NPC一覧を上、能力値とレーダーチャートを上下、能力値を2カラムに落とす。 タブレットの縦持ちで使うことを前提にしているため、 横スクロールが出る状態は作らない。

表に無いキーワードは、入力した文字列のまま「失敗」と同じグレーのバッジで表示される。 成功を表す語であっても失敗色になるため、卓上で意味が逆に伝わる。

ただし技能判定ダイアログで足した自由枠（3.2）は例外で、 琥珀色（#b45309 / bg-custom）のバッジになる。 ルール上の成功段階と、シナリオ都合の枠とを見分けられるようにするため。

ダイス目由来の呼称のうち、次の3語だけが認識されない （「ダブル」「トリプル」「ファンブル」は使えるのに、これらは使えない）。
  • シングル → 成功 と書く
  • カタストロフィ（末尾が「ィ」）→ カタストロフ と書く
  • 大惨事 → 災厄級成功 と書く
🎲技能判定ダイアログから挿入した場合は認識される形式（- 成功: など）が入るため、 この問題は手打ちしたときだけ起きる。
2026-08-31: この表を実装に合わせて訂正した。 それ以前の記述は シングル / カタストロフィ / 大惨事 を 有効なキーワードとして挙げ、バッジ文言も「通常成功」「効果的」「大惨事」などと書いていたが、 いずれも実装と一致していなかった。 キーワードを増やすのではなく仕様書側を実装に合わせる方針を選んでいる。

5. 非機能要件

  • レスポンシブ／モバイルファースト — Androidタブレット（横向き・縦向き）に最適化し、ボタンのサイズは最小でも 44px × 44px を確保してタップミスを防ぐ。
  • 完全なオフライン動作
    • 保存に通信を伴わないため、電波の無い会場や機内モードでも支障なく執筆できる。
    • ネットワークを使うのは Google Fonts の読み込みのみ。読み込めない場合も代替フォントで動作する。
  • 保存容量の上限への対応
    • 保存領域の上限を超えた場合、保存が黙って失敗しないよう、書き出しを促すメッセージを表示する。 上限そのものは IndexedDB への移行で大幅に緩和した（保存方式設計書）。
    • NPCのアバター画像を base64 で保持しているため容量を大きく消費する。上限に達する主因はこれである。
