シナリオ基本情報設計書

シナリオの基本情報（タイトル・サムネイル・概要などの見出しと本文・難易度などのレベル表示）を、 どんな形で持ち、どう表紙としてプレビューとPDFの先頭に出すかと、なぜその形にしたかを残す。 項目の種類を足すとき・表紙の見た目を変えるときに読むこと。

1. 守備範囲

TRPGのシナリオには、本文の前に置く「基本情報」がある（プレイ人数・推奨技能・プレイ時間・難易度・ロスト率など）。 中身の構成は作者によってさまざまなので、決め打ちの欄ではなく、汎用の項目を好きな順に並べる形にした（2026-10-05 の要望）。

要素内容
タイトルシナリオ名。ヘッダーのタイトル欄と同じもの（§3）
サムネイル画像1枚（§4）
見出しと本文「概要」と本文のような組。主に普通の文章を書く
レベル「難易度 ★★★☆☆」のような、項目名と記号の数の組。記号の種類と段階の数を選べる。見出しの子にもできる

編集はモーダル（「📘 シナリオ基本情報」）で行い、プレビュー（＝紙）の先頭に表紙として出す。 本文の記法（04 記法設計書）とは別の入口であり、本文には何も書き込まない。

2. 項目の形

basicInfo: {
  thumbnailId: "…",             // avatars ストアのキー（§4）
  items: [
    { id, kind: "section", heading: "概要", blocks: [
        { id, kind: "subheading", heading: "プレイ人数", body: "2〜3人" },
        { id, kind: "subheading", heading: "想定時間",   body: "3〜4時間" },
        { id, kind: "level", label: "難易度", value: 3, max: 5, symbol: "star" } ] },
    { id, kind: "section", heading: "傾向", blocks: [
        { id, kind: "text",  body: "探索が中心のシナリオです。" },
        { id, kind: "level", label: "戦闘", value: 1, max: 3, symbol: "star" },
        { id, kind: "level", label: "探索", value: 3, max: 3, symbol: "star" },
        { id, kind: "text",  body: "※戦闘は回避できます。" } ] },
    { id, kind: "level", label: "難易度", value: 3, max: 5, symbol: "star" }
  ]
}

最上位の項目は「見出しと中身の組（section）」と「単独のレベル（level）」の2種類で、好きな順に並べる。 section の中身（blocks）には、本文（text）・小見出し（subheading）・レベルを混ぜて並べられる。 要望の「レベルは任意の見出しの子として、通常の文章にまぎれて使われる場合がある」を、そのまま形にしたものである。

2.1 小見出し（2026-10-05 追加）

見出しには「概要」「あらすじ」、小見出しには「プレイ人数」「想定時間」が入る想定である（要望）。 小見出しは項目名と内容の組（{ heading, body }）として見出しの中に置き、 台本では「項目名｜内容」の表の1行として出す（§5）。

却下した案理由
小見出しを見出しと同じ入れ物にして、中に本文やレベルを入れられるようにする（3段の入れ子） 「プレイ人数｜2〜3人」のように、小見出しの中身はほとんどが短い値1つ。入れ子にすると編集画面が深くなり、値1つを書くのに欄を2つ開くことになる。
小見出しを見出しの外（最上位）にも置けるようにする 要望は「見出しの下の小見出し」。見出しの無い組が必要なら、見出しを空にした見出しの中に置ける。
却下した案理由
「概要」「プレイ人数」「推奨技能」などの決め打ちの欄を持つ 作者ごとに構成が違う。足りない欄は書けず、使わない欄は空のまま残る。汎用の項目にしてほしいという要望そのものに反する。
見出しの組を「見出し＋本文1つ＋レベルの一覧」の固定の形にする（本文の後ろにレベルが並ぶ） 本文とレベルを混ぜて並べられない（「本文 → レベル → 注意書き」が書けない）。
見出し・本文・レベルを平らな1列に並べ、見出しが後ろのものを束ねる（本文の # 見出しと同じ考え方） 見出しの後ろに、どの見出しにも属さない単独のレベルを置けなくなる（後ろのものはすべて直前の見出しに吸われる）。編集画面で「見出しと本文の組」が1つのまとまりに見えない。
レベルを本文の記法で書く（[レベル:難易度/3/5/★]） 記号を押して段階を決める・記号の種類を一覧から選ぶ、といった画面の操作ができず、記法を覚えないと使えない。本文の中でレベルを使う入口としては将来の拡張に残す（§8）。
  • 形は normalizeBasicInfo() が保証する。保存・読込・書き出し・読み込み・移行・作業状態の復元の、すべての入口を通す。この機能より前のシナリオには basicInfo が無いので、空の基本情報に均す。
  • レベルの段階の数（max）は 1〜10。それより多いと一目で数えられない。値（value）は 0〜max に丸め、記号は LEVEL_SYMBOLS に無いものなら星にする。
  • ID は読み込んだJSON由来の任意の文字列でありうる。編集画面では onclick の文字列に埋め込まず、エスケープした data- 属性で渡す（§6）。

3. タイトルは1か所にだけ持つ

タイトルの実体は従来どおりシナリオの title（ヘッダーのタイトル欄）で、basicInfo には持たない。 モーダルのタイトル欄は、ヘッダーの欄を書き換えて同じ自動保存の経路（handleInput()）に乗せるだけである。

2か所に持たないこと。タイトルはシナリオ一覧の表示名と、書き出しファイル名にも使っている。 基本情報側に別のタイトルを持つと、一覧の名前と表紙の名前が食い違う。

4. サムネイル

  • 実体は NPCの立ち絵と同じ avatars ストアの Blob で、基本情報は thumbnailId で指す。 画面に出すときだけ blob: URL を作って thumbnailUrl に入れ、保存するときは落とす（stripBasicInfoUrl()）。 理由と object URL の解放の決まりは 03 保存方式設計書 §3.3 と同じである。
  • ストア名は avatars のままにした。名前を変えるには DB の版を上げる必要があり、 版を上げる前に済ませるべき対策（onblocked）がまだ無いため（03 §3.2）。
  • 画像の棚卸し（pruneAvatars()）は、立ち絵とサムネイルの両方を「使用中」として数える。 片方を数え忘れると、使っている画像を消してしまう。
  • 読み込み時に長辺 1600px へ縮める（立ち絵は1024px）。サムネイルは紙の幅いっぱい（A4で約180mm）に出るので、立ち絵より大きく残す。
  • JSONの書き出しでは、立ち絵と同じく data URL に戻して thumbnailUrl に入れる（thumbnailId は書かない）。読み込みで Blob へ移し替える。

5. 表紙の出し方

updatePreview() が、本文の変換結果（parseMarkdown()）の前に buildScenarioCoverHTML() の結果を置く。 本文の記法とは入口が別なので、parseMarkdown() には混ぜない。

  • 並びはサムネイル → タイトル → 項目。本文とは太い線で区切る。
  • タイトルが既定の「無題のシナリオ」のままで、サムネイルも項目も無いときは、表紙ごと出さない。 基本情報を使わない人のプレビューと紙の先頭に、「無題のシナリオ」が大きく出るのを避けるため。 タイトルだけを付けたシナリオでは、表紙はタイトルだけになる。
  • 並んだ小見出しとレベルは、1つの「項目名｜値」の表にまとめる（coverFieldsHTML()）。項目名の幅が揃い、値の頭が縦に揃う。 「プレイ人数｜2〜3人」「難易度｜★★★☆☆」が同じ表に並ぶ。項目名の列は長くても14字ぶんで折り返し、値の列は長い内容を折り返す。 小見出しの名前も内容も空のものは出さない（足しただけで書いていない欄）。
  • 表紙の見出しは、下線の小さな見出しにした。本文の ## 小見出し（ティールの左線）と同じ見た目にすると、どちらの見出しか分からなくなる。
  • 本文は文字色の記法と改行を活かす（renderInline()。04 §4 の順序を守る）。
記号は和文フォントで描くこと。 本文と同じ欧文優先のフォント（Inter・Segoe UI）を当てると、● は欧文フォント・○ は和文フォントのように 記号ごとに別のフォントで描かれ、大きさが揃わなかった。 記号の色は、暗い編集画面と白い紙の両方で読める中間の濃さにしてある（LEVEL_SYMBOLS）。
表紙に「編集」ボタンを置かない。 プレビューは台本の紙面を見る場所であり、操作のボタンは置かない（v1.9.1 で情報一覧のボタンをプレビューから移したのと同じ理由。 04 §9.5）。

6. 編集画面

入口理由
ヘッダーのタイトル欄の隣「📘 基本情報」 タイトルの続きを書く場所なので、タイトルの隣に置く。幅が足りないときは名前を消してアイコンだけにする（07 §3.6）。
コマンドパレット・Alt+B ACTIONS の basic-info。本文を書き換えないので、場面図の表示中も受け付ける。
下部パネル — 置かない パネルは768pxで残り14pxしかなく、1280pxでも正式名のまま収まる余地が無い。基本情報はシナリオごとに一度書けば済む頻度の低い操作なので、07 §3.2 の決まりに従ってパネルには足さなかった。
  • 項目の欄は、追加・削除・並べ替えのときだけ作り直す。文字の入力は値を書き換えるだけにする（作り直すとフォーカスと入力途中の文字が失われる。NPCのメモと同じ）。 記号を押したとき・段階の数や記号の種類を変えたときは、その記号の列だけを描き直す。
  • 記号を押すとその段階になり、今の段階と同じ記号を押すと1つ下がる。こうしないと 0 に戻せない。 記号のボタンは指で押すので、高さをタップ領域の下限44pxに保つ（01 §5）。
  • 並べ替えは ↑ ↓ のボタンで行う（見出しの中身は見出しの中でだけ動く）。動かした後は押したボタンにフォーカスを戻し、続けて動かせるようにする。ボタンは巻末の画面と共用する（entryToolsHTML()）。
  • 削除は、中身のある項目だけ確認する（空の項目は黙って消す。NPCのメモと同じ）。
  • 見出しの中には「＋ 本文」「＋ 小見出し」「＋ レベル」で足す。足した欄から打ち始められるようにフォーカスを移す（小見出しとレベルは項目名の欄、本文は本文の欄）。
  • 操作は #bi-items への委譲で受ける。項目の ID は data-bi-id 属性に入れ、CSS.escape() を通して探す。
基本情報のボタンを足したとき、1280pxでヘッダーの「一覧」「保存」などが1文字ずつ縦に折れた。 これを機にヘッダーの要素は文字を1行に保つようにし、幅が足りないときの詰め方を決めた。 詰め方は 07 操作の入口設計書 §3.6 にある（ヘッダーに要素を足すときはそちらを読むこと）。

7. テンプレート（2026-10-05 追加）

基本情報の構成（見出し・小見出し・レベルの並びと名前）に名前を付けて保存し、別のシナリオで呼び出せる。 書き手ごとに「いつもの基本情報の形」があり、シナリオのたびに同じ見出しと小見出しを作り直していたため（要望）。

決めたこと理由
シナリオではなくこの端末の設定（localStorage の trpg_basic_info_templates）に持つ 「いつもの形」はシナリオをまたいで使うもの。マイパレット・ショートカットと同じ扱い（03 §3.1）。JSONの書き出しには含まれない。
既定では構成だけを保存し、「本文や値も含める」にチェックしたときだけ中身も保存する 要望は「構成」の保存。プレイ人数の「2〜3人」やレベルの段階はシナリオごとに違うので、残すと書き換え忘れの元になる。注意書きのように毎回同じ文を使う人のために、中身も残せるようにした。
構成として残すもの：見出しと小見出しの名前、レベルの項目名・段階の数・記号、本文の欄があること レベルの段階の数と記号は「どう表すか」の決めごとで、構成の一部。本文の欄は空のまま残し、そこに本文を書くことを示す。
タイトルとサムネイルは含めない シナリオごとに必ず違う。
呼び出しは「置き換える」と「後ろに足す」の2つ 新しいシナリオでは置き換え、書きかけのシナリオに足りない部分だけ足したいときは後ろに足す。置き換えるときは、今の項目に中身があれば確認する。
名前は重ならないようにし、同じ名前で保存したら上書きの確認を出す。30件まで 名前で見分けるので、重なると区別できない。名前は一覧の欄でその場で変えられる。
  • テンプレートには項目の id を持たせない。呼び出すたびに振り直す（basicInfoStructure() で写しを作り、normalizeBasicInfo() を通す）。同じテンプレートを2回足しても、項目の id が重ならないように。
  • 読み込むときは基本情報と同じ正規化を通す。壊れた値・名前の無いもの・重複した名前は読み飛ばす。
  • 入口は基本情報の画面の「項目」の右端の「📋 テンプレート」。押すと保存と一覧の欄が開く。

本文の中でもレベル表示を使う ブロック記法を足す（04 §7.1）。描画は coverFieldsHTML() / levelSymbolsHTML() を使い回せる。 挿入には段階と記号を選ぶ画面が要る（07 §6 の「選ぶ画面を開く操作」）
