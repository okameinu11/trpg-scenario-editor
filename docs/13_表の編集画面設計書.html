表の編集画面設計書

表（[表]）をマス目に書いて作る・直す画面について、どこから開くか・画面の中で表をどう持つか・ 確定したときに記法へどう書き戻すか・どんな操作を置いたかを、なぜその形にしたかとともに残す。 表の記法そのもの（| の区切り・見出しの指定・結合の印・寄せ・改行）は 04 記法設計書 §12 にある。 編集画面の操作を足すとき、表の記法を変えるとき（書き戻しも直すことになる）に読むこと。

1. 守備範囲

表は v1.17.0 で記法として入ったが、作る手段は記法を手で書くことしかなかった（「表を挿入」はひな形を入れるだけ）。 2026-10-14 に「表追加用のボタンを追加して、グラフィカルに簡単に追加できるように整備したい」との要望を受け、 マス目の上で行・列・結合・寄せを決め、確定すると記法を本文に入れる画面を足した。 同時に、記法に寄せ・セルの中の改行・見出しの列・見出しの無い表・セルの結合を足している（04 §12）。

2. 開き方

入口開くもの
下部パネルの「本文」タブの「📊 表」、コマンドパレットの「表」 カーソルが [表] の段落の中にあれば、その表を直す。
文字を選んでいれば、選んだ行から表を作る（| で始まる行は表の行として、ほかの行はタブで区切る。表計算ソフトから貼った行を表にするため）。
どちらでもなければ、3行×3列の空の表を作る（1行目は見出しの行）。
プレビューの表をダブルクリック その表を直す。原文へは飛ばない（画面の「原文へ」で飛べる）
  • 作ると直すを1つのボタンにした。どちらをしたいかはカーソルの位置で分かる。 ボタンを2つにすると、表の中にいるのに「作る」を押して表の中に表を入れる、という取り違えが起きる。 画面の見出し（「📊 表を作る」／「📊 表を直す」）で、どちらで開いたかを示す。
  • プレビューのダブルクリックは編集画面を開く（2026-10-14、利用者が選んだ）。 NPCカードをダブルクリックするとNPC管理が開くのと同じく、「書いた画面」を開く形にそろえた（11 §3.4）。 表は記法のまま読むより、マス目で見たほうが直しやすい。
  • 原文の小窓（11 §4）を開いているときにプレビューの表をダブルクリックしたら、小窓を先に確定し、描き直したあとの同じ表（何番目の表か）を開く。 小窓の中に書いた表は、小窓の中でカーソルを置いて「📊 表」を押せば、小窓の欄に書き戻す。
  • 「📊 表」は下部パネルに独立したボタンとして置いた（利用者が選んだ）。パネルの幅が尽きたので、パネルを分類のタブにした（07 §3.2）。

3. 表の持ち方と書き戻し

3.1 画面の中では、結合を範囲で持つ

{ title, headerRow, headerCol,
  align:  ['', 'center', 'right', ...],      // 列ごとの寄せ。'' は既定（左）
  cells:  [['場面', '目安'], ['導入', '25分'], ...],  // 長方形。結合で隠れるセルは空文字。改行は \n
  merges: [{ r0, c0, r1, c1 }, ...] }        // 結合した範囲（左上と右下）

記法では結合を印（< ^）で書くが、画面の中では範囲で持つ。 行や列を足し引きしたとき、範囲なら端の番号を1つずらすだけで済む。印のまま持つと、足した行の印を前後の印から決め直す処理が要り、取り違えやすい。

開くとき（tableModelFromSource()）は、プレビューを描く処理と同じ parseTableSource() と computeTableMerges() で読む。 読み方が1つなので、プレビューで見えている表と、開いたマス目が食い違わない。 結合できなかった印（長方形にならない、左や上にセルが無い）は、プレビューと同じく文字のまま残す。

3.2 確定すると、表の段落ごと書き直す

確定すると tableModelToSource() で記法に戻し、開いた表の段落を丸ごと差し替える（作るときは、選んでいた範囲かカーソルの位置に入れる）。 差し替えは editFieldRange() を通すので、Ctrl+Z の1回で戻る（10 元に戻す設計書 §2）。

書き戻し方理由
結合は、左上のセルに中身、同じ行の右側に <、下の行の左端に ^、残りに <computeTableMerges() が長方形として読める書き方のうち、いちばん単純な形（04 §12）
セルの中の改行は <br>記法では1行が表の1行なので、改行をそのまま書けない
セルの中の縦線（| ｜）は ¦どちらもセルの区切りとして読まれる。見た目の近い文字に替えて、セルが割れないようにする
1文字だけの < ^ は全角（＜ ＾）結合の印と見分けられない。開いたときに文字のまま残っていた印も、ここで全角になって文字として確定する
区切りの行は、寄せを決めた列があるときだけ書く寄せの無い表に |---| の行を足すと、本文で読むときの雑音になる。
ただし中身の最初の行が区切りの行と見分けられない（| - | - |）ときは、中身として残すために書く
題名の ] は ］、改行は空白タグが途中で閉じる・段落が割れるのを防ぐ
作るときは前後を空行で挟む（すでにあれば足さない）表は段組みの外に出る全幅のブロックで、空行で区切った段落でないと表にならない（04 §12.2）
手で書いた表を編集画面で確定すると、書き方が整えられる。 両端の |・セルの前後の空白・全角の ｜・<BR/> の書き方・左寄せの :--（既定と同じなので書かない）・寄せの無い区切りの行は、上の形にそろう。 表の見た目は変わらない。直さずに閉じれば（取り消す・Esc）、本文には何も起きない。

4. 操作

4.1 ボタン

ボタンすること
行：＋上に／＋下に／削除選んでいる範囲の上・下に1行足す、範囲の行を消す（最後の1行は消せない）
列：＋左に／＋右に／削除同じく列で
寄せ：左／中央／右選んでいる列の寄せ。選んだ列がみな同じ寄せなら、そのボタンを押した状態に見せる
セル：結合／結合を解く選んでいる範囲を1つのセルにする／範囲に交わる結合を解く
1行目を見出しにする／1列目を見出しにする記法の /見出しなし と /見出し列（04 §12）。見出しのセルは、マス目でも地の色と太字で示す
  • ボタンは mousedown で既定の動きを止め、セルのフォーカスと選んだ範囲を外さない（下部パネルのボタンが本文の選択を外さないのと同じ）。
  • 結合した中身は捨てない。範囲の中の文字を読む順に改行でつなぎ、左上のセルに入れる。 表計算ソフトには左上だけを残して捨てるものが多いが、確かめずに押して消えるより、残ったものを消すほうが手戻りが小さい。
  • 見出しの行（1行目）と、その下の行は結合できない。記法でも結合しない（HTML の thead と tbody をまたげないため。04 §12）。 押したら理由を出して断る。見出しの行をあとから入れたときは、またがっている結合を解く。
  • 行・列を結合の中に足すと、結合を広げる。結合の左上の行・列を消すと、中身を残る側のセルへ移してから縮める。

4.2 範囲の選び方とキー

  • セルを押すと、そのセルが「今のセル」で、範囲の起点になる。Shift を押しながら別のセルを押すか、押したままセルをまたいでドラッグすると、起点からそこまでを選ぶ。
  • 範囲は、交わる結合をすべて含むところまで広げる（結合したセルの一部だけを選ぶと、結合も行・列の操作も意味が決まらない）。
  • Tab で右（行の最後なら次の行の先頭）、Shift+Tab で左へ移る。Enter で下へ移る。最後のセルから Tab、いちばん下の行から Enter で先へ進むと、行が増える。表計算ソフトと同じ動きで、行を足すボタンへ手を伸ばさずに書き続けられる。
  • セルの中の改行は Shift+Enter（Enter を下への移動に使うため。NPCのセリフの備考欄と同じく、改行に修飾キーを付ける形）。
  • Ctrl+Enter で確定、Esc で閉じる（書き換えていれば、捨ててよいかを確かめる）。
  • 日本語入力の変換中の Enter・Tab は、変換の確定に任せる（isComposing を見る）。

4.3 貼り付け

  • タブか改行を含む文字を貼ると、今のセルを左上にして、セルに分けて入れる。表計算ソフトでコピーした範囲（タブ区切り。改行やタブを含むセルは " で囲まれる）と、 Markdown や [表] の行（| で始まる行。区切りの行は読み飛ばす）を読める（parseClipboardTable()）。
  • 足りない行・列は足す。貼った範囲に重なる結合は解く（結合の一部に書き込むと、どのセルの中身か決まらない）。
  • 1つのセルに収まる文字（タブも改行も無い）は、ふつうの貼り付けのまま。

5. 却下した案

案却下した理由
プレビューの表に直接書き込む（contenteditable） プレビューは本文から描き直すもので、書いた内容を本文のどこへ戻すかの対応づけが壊れやすい（原文の小窓を作ったときと同じ理由。11 §4.1）。 編集画面は表の段落を丸ごと書き直すので、対応づけが要らない。
表計算ソフトのような部品（外部のライブラリ）を使う Kotro は index.html 1枚で、外部の依存を持たない（CLAUDE.md「なぜ1枚構成なのか」）。要る操作は行・列・結合・寄せ・貼り付けに限られ、自前で足りる。
表を本文の外のデータ（情報一覧のような一覧）に持ち、本文には参照だけを書く 本文で表の中身が読めなくなり、よそで書いた表を本文に貼るだけで使うこともできなくなる。表は本文の一部として読み書きするもので、 情報（PLへ渡す資料で、本文とは別にコピーして使う。04 §9）とは役割が違う。
画面の中に、仕上がり（プレビューと同じ見た目）を並べる 紙面のCSSは #preview-area を付けて書いてあり（12 §3）、画面の中では当たらない。 見出し・寄せ・結合はマス目で見えるので、文字色（{赤:…}）だけは確定したあとのプレビューで見る。
セルを1つずつ選ぶ形にして、選んだセルの中身を下の1つの入力欄で書く（表計算ソフトの数式バーの形） どのセルを書いているかと、書いている文字が離れた場所に出る。台本の表のセルは短い文が多く、マス目の中で直接書けるほうが速い。

6. 将来拡張の入り口

やりたいこと触る場所
セルの文字に色を付けるボタン今は {赤:…} を手で書く。セルの入力欄の選択範囲を色の記法で囲む処理（文字色の applyColor() と同じ考え方）を、編集画面の操作に足す
行・列の並べ替え（ドラッグ）runTableAction() に操作を足す。結合を範囲で持っているので、並べ替えで結合が割れるときは、行・列の削除と同じく解く・縮める
範囲を選んでコピー（表計算ソフトへ貼れるタブ区切りで）選んだ範囲（tableEdit.sel）の cells をタブと改行でつなぐ。貼り付け（§4.3）の逆
記法を足す（列の幅など）先に 04 §12 で記法を決め、parseTableSource()（読む）と tableModelToSource()（書き戻す）の両方を直す。片方だけ直すと、編集画面で確定したときに指定が消える
